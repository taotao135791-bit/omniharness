| Row | Codex CLI | Codex Desktop / IDE | Claude Code |
|---|---|---|---|

## 5. Implications for OmniHarness

Ten concrete requirements to meet or exceed the parity bar set above:

1. **OS-enforced sandbox with workspace-scoped defaults.** Ship Seatbelt (macOS) and bwrap (Linux) enforcement where the agent can write only to the workspace + temp dirs and has no network by default, with `.git` and harness config dirs protected read-only inside writable roots — matching both Codex (`sandbox_mode = "workspace-write"`, protected paths) and Claude Code (Bash sandbox defaults). Network access must be an explicit, allowlist-first opt-in.
2. **Layered, documented config hierarchy.** A single config format (ours is TOML/JSON) with at least user / project / local scopes, a defined precedence order, per-project trust gating for capability-granting config, and a managed/enterprise layer that cannot be overridden locally. Both competitors now ship MDM/server-delivered managed settings; this is table stakes for org adoption.
3. **Instruction-file chain, not a single file.** Discover instruction files from global scope down through the repo tree to cwd (AGENTS.md-compatible), concatenate in precedence order, enforce a byte budget, and support per-directory overrides — OmniHarness already reads AGENTS.md; we must document and test the full discovery/precedence semantics, not just "reads the file".
4. **Skills on the open agentskills.io standard with progressive disclosure.** Both Codex and Claude Code converged on SKILL.md + YAML frontmatter + optional scripts, loading only name/description until invoked (context-capped listings). OmniHarness skills must support: explicit invocation, description-based implicit invocation, disable-without-delete config, repo/user/system scopes, and frontmatter policy fields (tool allow-lists, implicit-invocation toggle). Avoid inventing a divergent format.
5. **Lifecycle hooks with a trust model.** Provide hooks on at minimum: session start/end, prompt submit, pre/post tool use (with blocking + input-rewrite capability), permission request, compaction, and subagent start/stop — with matcher filtering and a per-hook trust/review gate (Codex pins trust to hook hash; Claude Code gates via settings trust). Command handlers first; prompt/agent handlers can follow.
6. **Deny-first permission rules plus granular approval routing.** Implement allow/ask/deny rules with deny-always-wins precedence, command-prefix and path glob specifiers, per-subcommand evaluation of compound shell commands, and persistent "don't ask again" storage. Add a granular approval policy (auto-approve some categories, always-prompt others) and an optional reviewer-agent pass — Codex's `auto_review` is the differentiator to beat.
7. **First-class MCP client with production controls.** stdio + streamable-HTTP transports, OAuth, per-server `required` semantics (fail closed in headless runs), per-server tool allow/deny lists, and namespaced tool naming so hooks and permission rules can target MCP tools (`mcp__server__tool` pattern). Running OmniHarness itself *as* an MCP server is a cheap parity win (both competitors do this).
8. **Sessions, resume, and headless mode as one design.** Persistent sessions with resume/fork, plus a non-interactive mode that streams machine-readable events (JSONL), supports JSON-Schema-constrained final output, reads stdin as context, and lets CI pin sandbox/approval flags explicitly (Codex `exec --json --output-schema`; Claude `-p --bare --output-format`). Session lookup should be project/worktree-scoped.
9. **Worktree-isolated parallel agents with handoff.** Each background/parallel agent gets its own git worktree (detached HEAD, shared `.git`), with a `.worktreeinclude`-style mechanism for copying needed gitignored files and a handoff flow to merge work back to the user's checkout. Pair this with subagents that run in isolated context windows with configurable concurrency caps and per-role model/tool config, returning summaries to the main thread.
10. **Automations + extensibility packaging.** Scheduled/recurring background tasks that run against a project or an isolated worktree (Codex scheduled tasks; Claude Code desktop scheduled tasks), and a plugin format that bundles skills + hooks + MCP config + subagents into one installable, namespaced unit with a marketplace/distribution story and admin allow/block lists. Memory (persistent instruction files + agent-written auto memory with a load budget) should ride on the same file-based, inspectable storage.

Items deliberately out of scope for parity claims: exact UI surfaces (desktop app vs TUI), cloud-hosted task execution, and telemetry/OTel export (both competitors treat these as opt-in extras, not core agent capability).
